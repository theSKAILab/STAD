Ontology Specification Draft

Abstract

STAD-MLS is a lightweight ontology module for describing the computational processes by which data are generated. It provides concepts for representing algorithms, their implementations and executions, and the parameters and parameter settings associated with them. The module adapts the Algorithm, Implementation, and Execution ontology design pattern and draws on relevant concepts from the Machine Learning Schema (ML-Schema), while omitting terminology specific to machine-learning workflows. STAD-MLS is designed as a reusable module and is used by the STAD ontology to describe the computational provenance of aggregate datapoints.

Introduction back to ToC

Computationally derived data are influenced not only by their input data but also by the algorithms, software implementations, and parameter settings used to generate them. Explicitly representing these aspects supports the interpretation and reuse of computational results and provides provenance about how they were obtained.

STAD-MLS provides a compact ontology for representing this information. It is based on the Algorithm, Implementation, and Execution (AIE) ontology design pattern and adapts a subset of concepts from the Machine Learning Schema (ML-Schema). While ML-Schema provides a more comprehensive model oriented toward machine-learning workflows, STAD-MLS focuses on the more general distinction between an algorithm, its concrete implementation, and a particular execution, together with the parameters and parameter settings involved. Corresponding STAD-MLS concepts are related to their ML-Schema counterparts using skos:related, maintaining an explicit connection to ML-Schema without importing its complete model.

STAD-MLS was developed as a separate module so that these computational provenance concepts can be reused independently of the core STAD ontology. Within STAD, the STAD-MLS module is used to describe how computational datapoints, including statistical aggregate datapoints, were generated and to distinguish the abstract transformation algorithm from details of its implementation and execution.

STAD-MLS extension: Overview back to ToC

STAD-MLS centers on five classes: Algorithm, Implementation, AlgorithmExecution, Parameter, and ParameterSetting. An Algorithm represents a sequence of instructions for solving a problem or achieving a goal independently of a particular implementation or execution. An Implementation represents an executable realization of an algorithm and is related to the algorithm it implements through implements. Implementations may specify the Parameters, they accept through hasParameter.

AlgorithmExecution represents a particular execution of an Algorithm using specific inputs and parameter settings. The executed algorithm is identified through realizes, while hasInput associates the execution with its parameter settings. A ParameterSetting specifies a value for a Parameter and is related to that parameter through specifiedBy. Together, these concepts permit computational provenance to be represented at different levels of detail, ranging from identifying the algorithm responsible for a computational result to documenting a particular execution and its parameterization.

The module is connected to STAD through the representation of computational inputs and outputs. In its use within STAD, an algorithm execution can take a STAD dataset as input, while STAD datapoints can be related to the computational process that generated them. This allows STAD to use the computational provenance model without incorporating these concepts into its core ontology.

STAD-MLS extension: Description back to ToC

STAD provides syntax for describing the spatial and temporal characteristics of aggregate quantities. This extension includes concepts for describing the algorithms and implementations used for data transformations. It is based on the Machine Learning Schema (MLS).
